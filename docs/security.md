# 安全モデル

## 信頼境界

Jevの回答は、実行可能な候補の選択です。任意コマンド、任意パス、任意の課金経路を生成させません。repoの文章、workerの報告、テスト出力はデータであり、runtimeの権限・予算を変更できません。API型が正しいことは、判断内容が正しい証明でもありません。

利用者の停止・取消し、危険パス、古いsnapshot、期限切れ・不明な作業、予算不足はruntimeで拒否します。Jevが承認しても、実測テストと独立レビューが現在のsnapshotに対応していなければACCEPT候補を作りません。

## ローカル実行の限界

**既定のworktreeとCLIフラグは、OS sandboxの代わりではありません。** 同じOSユーザーのコードは、ホーム、他workspace、認証ストア、ネットワークへアクセスできる可能性があります。既存CLIの設定や更新により内部挙動も変化します。強い隔離が必要な未信頼コードには、隔離済みのOS環境を使用してください。

標準レベルは `trusted-local`。未認証・未検証の環境を強制隔離済みと表示しません。制御層はpush/deployを行いませんが、worker内の任意コマンドをOSレベルで完全に禁止する製品ではありません。

## キーと送信

Jevキーは環境変数またはOS secret storeに分離します。worker・検証コマンドには制御キー、JVO変数、危険な環境フックを継承しません。テスト環境には一般のkey/token/secret変数も既定で除去します。プロジェクトの `.env` を自動読込しません。

コード断片・依頼・レビューは、選択したJev providerへ送信されます。明示信頼、除外glob、送信上限、既知キーとパターン検査を適用します。秘密検査は完全ではないため、機密リポジトリの承認と送信範囲の確認は必要です。provider endpointを変更する場合は、その送信先を利用者自身が信頼できることを確認してください。

APIエラー本文はそのままログへ出しません。ログ・TUIの制御文字、OSCリンク、危険な表示シーケンスを無害化します。

## 状態、Git、復旧

stateはプロジェクト外のprivateディレクトリに置きます。DB・token・ログは利用者専用の権限。local IPCは認証token付きUnix socketであり、ネットワークへダッシュボードを公開しません。

worktreeの実体、Git共通ディレクトリ、symlink祖先、許可パスを検査します。Git hook、署名、暗黙の自動GC、外部diff等を実行経路から外します。カスタムclean/smudge filterがあるリポジトリは、実行を始める前に停止して確認します。

一つのworkspaceには単一writer。共有資源のleaseは期限切れだけでは横取りしません。PIDの生存だけでなく生成時刻とプロセス群を照合します。既知の完了を観測できなければ `unknown` とし、確認なしに同じ副作用を再実行しません。

DB transactionだけで外部プロセスのexactly-onceを保証しません。outbox、冪等性、実行前後の検査と明示照合を組み合わせます。復旧時に消えたworktreeを別の場所へ黙って作り直しません。

## 明示反映

runの統合と、利用者のcheckoutへの反映は分けます。通常は `/apply` が必要です。元のHEAD、index、ファイルが変化していれば停止します。dirty基準を明示的に取り込んだ場合は、対象内容を照合してパッチ反映し、indexを勝手に変更しません。

`replay`、`metrics`、`export-eval` は保存済みのチェックポイントを読むだけです。Git/worker/APIを起動しません。書込中のWALがある場合は、暗黙checkpointをしないため先に `/exit` を求めます。

## 予算

JevのAPI試行数、worker起動数、実行時間、修正回数、並列数、ログ量を制限します。native CLIの追加請求・サブスク残量が観測できない経路では、正確な金額上限を保証しません。provider側で利用上限を設定できる場合は併用してください。
