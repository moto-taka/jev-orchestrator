# 報告を仕分けて、必要なものだけまとめて読む（0.3.0）

`jvo triage` は**保存した報告JSONを処理する任意のコマンド**です。通常のjvoに文章生成型の司令塔を追加するものではありません。外部端末を常時監視する機能でもありません。生成・tool進捗は、通常のjvoではもともと表示・保存だけでJevを呼びません。

## 流れ

```text
保存済みの報告
  ├─ 空のheartbeat → ローカルに保持
  ├─ 質問・失敗・完了・範囲変更・承認要求 → 必ず注意対象
  ├─ 秘密情報の疑い → ローカル確認のみ。Jevにもoperatorにも送らない
  └─ その他の曖昧な報告 → 許可した場合だけJevへまとめて分類
       ├─ 明確に通常の経過 → 原文を保存し、operatorへは送らない
       └─ 不確実・不正回答・障害・予算超過 → 注意対象へ
注意対象 → 保存して表示
         → 明示許可した場合だけ、選んだモデルへまとめて相談
```

`kind: progress` はworkerの自己申告なので、それだけを理由に捨てません。自由文中の明確な質問、失敗、完了、権限変更なども保守的に拾います。ただし正規表現やJevの判定に完全な検出を保証する能力はありません。日本語や婉曲表現を含む実際の報告で校正する必要があります。

## 使用例

```sh
# 既定はコードだけ。Jevキー不要、生成APIなし。
jvo triage reports.json

# 曖昧な報告だけJevで分類（API利用への明示許可）
jvo triage reports.json --allow-api

# 注意が必要な報告だけ、許可済みCLIモデルへまとめて読ませる
jvo models --json  # 保存済みprofile IDを確認（APIなし）
jvo triage reports.json --allow-api --operator=<profile-id> --allow-worker
```

`--operator` は既に利用者が許可したモデルを指定します。未許可モデルへ変更しません。Jevの仕分けをせず、ルールとまとめ読みだけを試す場合は `--allow-api` を付けずに同じoperatorを指定します。

ここでのoperatorは**助言専用**です。scope変更・リリース・権限付与・ファイル編集・タスク完了承認を実行しません。元のプロジェクトを渡さない空の作業場で、CLIの読取専用の役割と実行後のファイル検査を利用します。worktreeや読取用のプロンプトをOS sandboxとみなすものではなく、利用は信頼済みローカルCLIに限ります。

## JSON形式

```json
[
  {"id":"p1","kind":"progress","taskId":"API","text":"ファイルを編集中です。"},
  {"id":"q1","kind":"question","taskId":"UI","text":"AとBのどちらにしますか？"},
  {"id":"b1","kind":"blocked","taskId":"API","text":"テストが失敗しました。"},
  {"id":"c1","kind":"completed","taskId":"TEST","text":"確認が完了しました。"}
]
```

配列または `{"reports": [...]}` を受け取ります。idは重複不可、最大256件。kindは `unknown` / `progress` / `heartbeat` / `question` / `blocked` / `completed` / `scope-change` / `approval` です。省略するとunknownです。件数、本文、ファイル、API回数、operatorのbatch数に上限があり、超過を黙って切り捨てません。

## 分類と保存

曖昧な報告は最大12件ずつの独立したboolean質問としてJevへ渡します。通常とする閾値の初期値は0.99です。これは正解率99%の保証ではありません。重要と分かっている構造化イベントを、Jevの分類で通常報告へ格下げしません。

結果は `~/.local/state/jvo/triage/<id>/`（JVO_HOME指定時はその下）へ保存します。

- `intake.json`: API処理前のローカル入力控え。秘密らしい値は伏せます。
- `reports.json`: 全報告と仕分け結果。通常扱いした本文も含みます。
- `operator-<n>.json`: 任意のoperatorへの送信記録・応答。自動再送しません。
- `result.json`: 対象件数、Jev呼出し数・観測可能なusage、operator回数・usage、助言。

秘匿値は出力コピーでも伏せるため、完全な原本は利用者が指定した元ファイルです。元ファイルを変更・削除しません。`localOnly` は必ずローカルで確認してください。

operatorへはattentionだけを最大32KBずつ送ります。通常の報告を隠してプロンプトへ混ぜたり、全履歴を要約し直したりしません。複数batchは同じモデル・session・cwdへ追加します。session継続を確認できない場合は停止し、別sessionへ黙って置き換えません。容量不足や送信結果不明の場合も履歴を保持し、勝手に再実行しません。

## ご提示の比較と、測定を分ける

ご提示の記事には、報告をまとめるだけの効果と、Jevに仕分けさせる追加効果を別々に比較する重要な点があります。jvoでも、ルールだけ＋まとめ読みと、Jev仕分け＋同じモデルのまとめ読みを比較できます。ただしこの記事の33万→14万token等はjvoで再現測定した数字ではありません。

本実装では6件のテスト用報告について、明確な重要4件を必ず残し、曖昧な2件を一回の分類要求へまとめる制御を試験しています。classifierはfixtureであり、Jevの精度評価ではありません。

実測では同じ報告集合、同じモデル・設定・初期文脈、複数回の順序を変えた比較を使い、仕分けの誤り、重要報告の取りこぼし、通常報告の誤通知、全体の経過時間、cache読取を分けたusageを記録してください。表示されたtokenから未観測のサブスク追加請求額を0円やAPI標準料金と断定しません。

現段階は保存報告の仕分けと助言の経路です。自動運転する常駐司令塔・他社ターミナルの操作・ネットワークA2Aへの接続は追加していません。
